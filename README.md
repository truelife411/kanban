# 本地看板

这是一个使用 Python 标准库、SQLite 和原生浏览器技术实现的单机看板。它支持列和卡片管理、筛选与排序、历史归档、附件、JSON 导入导出以及包含附件的完整 ZIP 备份与恢复。

## 环境要求

- Python 3.10 或更高版本（项目使用标准库实现，并通过项目测试命令持续验证当前受支持版本）
- 支持 ES Modules 的现代浏览器
- 不需要安装第三方 Python 包

日期和时间字段使用应用内置的选择器，在支持的桌面浏览器中提供一致的日历、时间、清除、取消和确认操作；无需依赖或额外安装系统、桌面环境或浏览器自带的日期组件。

## 启动

在项目目录执行：

```powershell
python kanban.py
```

然后访问：

```text
http://127.0.0.1:8000
```

服务强制仅监听 `127.0.0.1`，不能通过环境变量改为局域网或公网地址。可按 `Ctrl+C` 停止服务。

## 测试

在项目目录执行完整测试：

```powershell
python -m unittest discover -s tests -v
```

## 外观与显示

- 提供十四套主题：薄荷绿、海盐蓝、豆瓣绿、黑白、陶土、赭石、天青、黛蓝、群青、秋香、玻璃、深海夜、极光和极光夜；首次使用默认选择薄荷绿。极光与极光夜采用磨砂玻璃面板，会在支持的现代浏览器中启用背景模糊，不支持时自动使用高可读性的实体半透明表面；薄荷绿以青绿为基底，页面用列底色（#C2E5D5），列、卡片、弹窗逐层递进更浅的绿（#D6F0E7 → #E9F8F2 → #F6FCF9），形成单色绿由深到浅的层次，不使用磨砂模糊。
- 主题与卡片描述显示偏好只保存在当前浏览器中，不会写入看板数据，也不会同步到其他浏览器或设备。
- 看板卡片描述默认展示两行。该设置只影响卡片在看板上的预览高度，不会裁剪、改写或丢弃已保存的完整描述内容；可在设置中改为不展示、一行、两行或完整展示。

## 数据目录

运行数据均位于项目目录中：

- `kanban.db`：SQLite 数据库，保存列、卡片和附件元数据。
- `attachments/`：附件文件，按卡片存放。
- `backups/`：迁移、导入、恢复和数据库安全备份使用的内部目录。
- `static/`：前端静态文件，不是用户数据。

请同时保护数据库与附件目录。服务运行时不要把直接复制 `kanban.db` 当作唯一备份方式，因为 SQLite 可能正在使用 WAL，并且附件文件不在数据库中。

## 环境变量

所有数值变量都必须使用十进制整数；大小限制的单位为字节。

| 变量 | 默认值 | 说明 |
| --- | ---: | --- |
| `KANBAN_PORT` | `8000` | 本机 HTTP 端口。监听地址固定为 `127.0.0.1`。 |
| `KANBAN_MAX_ATTACHMENT_BODY` | `104857600` | 单次附件上传请求体上限（100 MiB）。 |
| `KANBAN_MAX_ZIP_BODY` | `1073741824` | 完整备份 ZIP 上传上限（1 GiB）。 |
| `KANBAN_MIN_FREE_BYTES` | `536870912` | 备份、上传和恢复时要求保留的最小磁盘空间（512 MiB）。 |
| `KANBAN_MAX_ZIP_ENTRIES` | `100000` | 恢复 ZIP 允许的最大条目数。 |
| `KANBAN_MAX_ZIP_RATIO` | `200` | 恢复 ZIP 允许的最大压缩率。 |
| `KANBAN_MAX_ZIP_EXPANDED_BYTES` | `0` | ZIP 解压后总大小上限；`0` 表示不额外设置此项上限。 |

PowerShell 示例：

```powershell
$env:KANBAN_PORT = "8080"
python kanban.py
```

## 归档与永久删除

- **归档**会把卡片移入历史记录，保留卡片内容和附件，可随后恢复；删除列时，其中的活跃卡片也会归档。
- **永久删除**适用于活跃或已归档卡片，会删除卡片数据库记录、附件元数据和附件文件，并且不能撤销或从历史恢复。
- 永久删除不会自动创建备份。若附件仍有保留价值，请先下载附件或手动生成完整 ZIP 备份；删除完成后附件内容不可恢复。

## JSON 与完整 ZIP 的区别

### JSON 导出

“导出 JSON”保存列、卡片、归档历史及附件元数据，但**不包含附件文件本体**。它适合查看或迁移结构化看板数据，不适合作为含附件看板的完整灾难恢复备份。

导入 JSON 会替换当前看板数据。JSON 中即使存在附件元数据，也不会恢复缺失的附件文件；执行替换前，系统会先创建当前数据的完整 ZIP 备份。

### 完整 ZIP 备份

“完整备份（含附件）”生成 ZIP，其中包含：

- 一致性的 SQLite 数据库快照 `kanban.db`
- 已登记的全部附件文件
- 用于格式、数量、大小和哈希校验的 `manifest.json`

如果数据库登记的附件文件已经缺失，系统会拒绝生成不完整的 ZIP，并报告缺失项。

## 自动安全备份与保留策略

程序通过 `create_backup` 产生的正式 `kanban-*.db` 数据库安全备份最多保留最近 10 份。新备份成功发布后才清理更旧的超额文件；ZIP、临时文件和未知命名文件不在该轮换范围内。清理失败只会记录到标准错误，不会把已经成功的备份判定为失败。

完整 ZIP 制作过程中使用的 snapshot 数据库只是中间文件，ZIP 完成或失败后会被删除，不参与长期保留。

## 完整备份恢复

推荐在页面中使用“导入 JSON 或完整备份”选择本系统生成的 ZIP：

1. 上传 ZIP 后，系统先检查路径安全、条目数量、压缩率、manifest、数据库完整性以及数据库和附件哈希。
2. 页面显示列、卡片、归档和附件数量的恢复预览。
3. 确认恢复后，系统先为当前数据生成 `pre-restore` 完整备份。
4. 当前数据库和附件目录被替换为备份内容；失败时系统会尝试回滚原数据。
5. 恢复完成后刷新页面确认数据。

不要在服务运行时手工解压 ZIP 并覆盖数据库或附件目录。

## 安全边界

- 服务固定只接受本机连接，且没有用户登录、权限分级或多用户隔离功能。
- 本机其他进程或能够操作当前 Windows 用户会话的人仍可能访问服务和数据。
- 不要使用端口转发、反向代理、隧道或容器映射将服务暴露到不可信网络。
- 附件会保留原始文件内容；打开下载的附件前仍应按其来源进行安全检查。
- 恢复和 JSON 导入属于替换操作，应先核对文件与预览信息。

## 常见故障

### 端口被占用

若启动时报地址已被使用，指定其他本机端口：

```powershell
$env:KANBAN_PORT = "8080"
python kanban.py
```

### 页面无法打开

确认终端中的服务仍在运行，并使用启动输出中的 `http://127.0.0.1:<端口>`，不要使用局域网 IP。

### 备份提示附件缺失

数据库中存在附件记录，但 `attachments/` 下对应文件已经丢失。根据错误列出的路径恢复文件，或在卡片中清理缺失附件记录后再备份。

### 备份或恢复提示空间不足

清理项目所在磁盘空间，或在确认风险后调整 `KANBAN_MIN_FREE_BYTES`。完整备份需要同时容纳数据库快照、ZIP 临时文件和附件内容。

### ZIP 被拒绝

只使用本系统生成且未被修改的完整 ZIP。被修改、损坏、包含额外文件、哈希不符、路径不安全或超过配置限制的 ZIP 会被拒绝。

### 数据库被占用或无法写入

确认没有另一个服务实例正在使用同一项目目录，并检查 `kanban.db`、`attachments/` 和 `backups/` 的读写权限。不要把项目放在不可靠的只读或同步冲突目录中。
